# 小伟内容

用户贴素材即可开始。读取上下文、已有项目和本地偏好，替用户完成检索、选角度和衔接，不要求填写长表单。

## 短口令

| 用户说 | 执行 |
|---|---|
| 小伟内容：原稿或主题 | 默认写小红书标题正文、抖音口播与发布描述 |
| 写文案 / 改口吻 / 换标题 | 承接最近明确的内容项目，只做指定部分 |
| 出整套 | 文案加3:4、9:16封面；“横竖都要”再加16:9 |
| 只要小红书 / 抖音 / X | 只做指定平台；X写独立帖文，按内容需要决定是否线程 |
| 只出封面 / 沿用上套 | 使用当前稿件、明确的上一套风格和人物，调用封面Skill |
| 这版定了 / 以后照这个写 | 记录认可的具体稿件与偏好范围 |

裸指令没有可承接素材时，只问“这次写什么？”。不为简单改标题重新跑整套。

## 1. 读原稿和反馈

读取本机 `~/.local/share/xiaowei-content/profile.md`（若存在）及当前项目。读取用户已认可样稿；没有就以用户原稿为声音依据。生成稿、沉默、同意工作流程均不等于认可稿件。未认可稿件不进入正面样稿库。

保留作者身份、立场、数字含义和真实表达；不能用别人的经历补作者故事。区分已发生、未来计划和愿望。GMV不能改写成利润或个人收入。纠正原稿内部矛盾时保留原文并记录修订。

按内容选择个人故事、项目复盘、工具教程、模型对比或发布消息，不把所有稿件都套成个人奋斗故事。

## 2. 找对标并真正阅读

先查本地已保存且题材相符的案例；新题材、用户要求学习对标、明确否定现有写法时补充在线检索。复用案例的表达结构与当前事实核验分开：旧案例可供写法参考，版本/价格/能力仍需当前官方证据。

有 `agent-reach` 时读取其Skill，按可用后端检索；否则使用当前可用搜索或浏览工具。先找到少量能深入阅读的同类内容，再决定是否扩大。用户要求特定平台/数量时按要求覆盖，并如实记录失败，不用重复查询凑数。

每个采用的案例记录原作者、原帖URL、读取日期、可见层级（全文/发布描述/自动摘要/搜索摘要）、实际写法和对本稿的适用点。转推归原作者；自动摘要不能当口播逐字稿；未看视频不能声称分析前3秒。只拿到标题就只分析标题。互动数不能证明写法导致流量。

借鉴进入话题的方式、证据顺序和收束动作，独立写当前稿件；不搬运独特原句。参考来源和可选组件见 [sources.md](references/sources.md)。

访问失败先用受支持的替代方式；仍失败则交代具体缺口，利用已读案例与原稿继续可完成部分。用户指定“必须看完某原帖才能写”时，缺口会阻断依赖该原帖的写作。

## 3. 分平台写作

每篇只承诺一件正文确实交付的事。先明确刷到的人为什么继续看，再写开头；标题不是把原稿压缩成一句摘要。

- 小红书：从读者能识别的处境、问题或动作进入，再交代作者经历/方法。正文可直接阅读，避免口播逐字搬运。
- 抖音：先写说得出口的开头和完整口播，再单独写发布描述。前几句话尽快进入事情，不先报栏目。时长按实际试读核验，字数估计不能叫已测时长。
- X：围绕一个进展、判断、实验或问题组织，证据紧接判断；不用原封不动的两平台标题与标签。

标题在内部探索不同角度，默认交付一个推荐标题；用户要选项时最多先展示三个有实质差异的方向。没有证据的成绩、冲突、亲子对话、亲测结论都不能为了吸引人而添加。

写完核对：标题的问题正文是否回答；每段是否有新信息；作者原来有力量的表达是否被磨成套话；后续内容承诺是否具体且来自原稿。删除“分享干货、记录成长”等无信息替代句。不同平台若只有字数区别，重新组织。

可调用本机 `write-credible-content-zh` 做事实与声音审校；商单需要时才用 `native-content-writing-zh`。这些组件缺失时按本文件完成文本工作，不自动下载安装，也不声称已调用。

## 4. 接封面

默认文案模式到此交付，不自动花时间生图。用户已说“整套”时，选出推荐稿并做完自检后直接接封面，不新增标题审批步骤；用户明确说“先审文案”才停在文案。

执行整套前定位已安装的 `generate-xiaowei-covers/SKILL.md`；本仓库内可在当前Skill实际目录的 `../../SKILL.md` 找到。先读其规则。缺少该组件则完成文案并说明图片未生成；不要用自制海报流程冒充它。

将本次选定文案、精确封面短句、事实来源、人物参考和平台画幅交给封面Skill，写入其 `COVER_PROMPT.md` / `FACTS.md`。封面不能另起主题或添加正文没有的收益。沿用其随机/指定样式选择器；随机只作用于可用视觉样式，同一批保持人物和主题。读取已锁定STYLE_SELECTION，续改不重新抽签。用户明确排除的样式在选前处理；没有可用样式时说明冲突，不能假装完成随机选择。

3:4、9:16和指定横版分别排版，核验文字、人像与实际像素；不把PNG叫可编辑图层或把目标像素叫实际高清。

## 5. 保存、续改与短交付

一件内容用一个项目目录；默认位于本机 Downloads，名称为 `小伟内容-日期-主题`，重名时新建后缀而不覆盖。原稿、引用、平台稿、封面放在一起。持续状态按 [project-state.md](references/project-state.md) 保存，记录文字与图片的版本对应关系。

偏好、原稿和完整第三方案例留在本机；仓库只放通用流程、来源说明与无隐私示例。对Skill的推送授权不代表可以顺带公开稿件、家庭信息或账号数据。

“改口吻”保留事实与已选主题；“换标题”核对正文是否仍兑现；“换风格”保留文案。影响图片的文案变更后将旧封面标记待更新，用户只改文字时不擅自重生图片。

默认直接给成稿与可点击文件；文件较多时只给推荐标题、主要结果和素材入口，不倾倒流程、评分和候选清单。只有用户要复盘才展开研究说明。社媒发布与GitHub推送另按当前请求执行，不由“出整套”自动授权。
