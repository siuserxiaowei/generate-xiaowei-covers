# 按内容选风格，一次锁定

这是一套小伟个人 IP 封面入口。先区分用途：小伟视频系列默认统一 `series`，保持人物与大字拼贴语言，按主题独立变化配色、布局、场景和动作。读 [series-cover.md](series-cover.md)。其它用途和明确的跨风格实验保留七个历史预设。内容路由决定“讲什么、用什么证据”，风格决定“怎样呈现”；两者独立。

## 选择与复用

```bash
node "$SKILL_DIR/scripts/select-cover-style.mjs" <project-dir> --style impact
node "$SKILL_DIR/scripts/select-cover-style.mjs" <project-dir> --style 阿囤囤 --ratios 3:4,9:16,16:9
node "$SKILL_DIR/scripts/select-cover-style.mjs" <project-dir> --style random --seed my-replay --ratios 3:4,9:16
node "$SKILL_DIR/scripts/select-cover-style.mjs" --list
```

- 未指定风格时：视频系列传 `--style series`；其它用途按内容判断。新项目省略风格会报错。视频系列的“随机生成”在相关配色/构图/场景/动作/对象内变化；仅明确跨风格随机探索才传 `--style random`。
- 用户指定风格时：按指定执行，不抽签。明确要求“多套不同风格”时选不同预设，每套独立文件夹。
- 同一项目再次执行：复用 `STYLE_SELECTION.json` 中的完整风格快照和 seed，避免9:16和横版变成另一种风格。
- 同一 seed 与同一版本预设顺序能复现风格选择；它**不保证**图片模型逐像素复现。
- `STYLE_BRIEF.md` 给出本次选中的视觉、字体、人物、禁用项与各画幅构图。读取它后执行，只选中一个风格即可，无须载入外部 Skill。
- 改主题、重新随机或改变已确定画幅时，创建新的任务目录；不覆盖上一套成品。

## 画幅与固定识别

- 未约定平台：默认小红书3:4 + 抖音9:16。
- “横竖都要”：3:4 + 9:16 + 通用16:9。
- 只指定一个平台/比例：按指定输出；公众号21:9配独立1:1，脚本自动补齐。
- 同批共用人物来源、配色、字体与内容主张，各画幅单独构图。
- series及其它预设可按主题改变人物位置与占比；用户明确指定位置时优先满足，不随机换脸、换标题、增加收入数字。
- 原照中的背景不等于本次文稿地点。没有视频/截图时，不能为了套工具风格伪造软件界面。
- 原仓库的浅色纸张、黄色强调与固定左下人物是 `original` 的基准，不强加给其它预设。
- 9:16安全区是保守排版约定，不是声称已验证的永久平台规则。发布前用实际上传预览核对。

## 两条生成路径

### original / editorial

使用既有 `assets/templates/vertical.html` 或 `wechat.html` 的项目骨架。在任务项目中按所选风格改写排版；editorial 将标题改为宋体、使用纸纹/墨洗、大照片与窄边注，不添加页面级网格。使用现有 `render-covers.mjs` 导出。

9:16、16:9需单独增加固定尺寸 `data-export` 画板；渲染器已有任意节点尺寸支持。可以使用2倍CSS布局栅格化导出，不能把低分辨率PNG放大后声称原生高清。保留 `data-text-safe`，修复真实溢出。

### series / atutun / gbro / oil / baoyu / impact

遵循当前环境内置 imagegen 的调用契约；读取原照片后，将它作为身份参考，先保存完整的 `prompts/<ratio>.md` 再生图。优先生成3:4母图，检查文字、脸和手，再用母图 + 原照片重新生成其它画幅。

每个画幅输出一张完整封面，不生成多图拼版冒充成品。人物一致性靠原图约束并目视检查，不能承诺照片级像素不变。必须保留实际尺寸与原始文件路径。标题错字或构图失败通过内置生图工具定点修正；不使用HTML/Python后贴文字冒充生图质量。

用户明确要求人物像素完全不变或必须拖动图层时，说明生成图片的限制，保留指定风格并采用用户授权的确定性图层制作方式；不要擅自把风格换成另一套。

内置生图不可用时，完成可复用提示词并明确图片尚未生成；不能把HTML仿制品称为某个生图预设的实际结果，也不自行切换付费外部服务。

## 交付与打开预览

- 文稿只需提供主题即可开始。个人故事提炼一句主标题与一句短副标题；不把整篇口播塞进封面，不把自述GMV改写成利润或已实现收入。使用者提供的经历记为自述，封面编辑文案另行标明。
- 生图的后续画幅提示词明确写出“保持项 → 修改项 → 目标效果 → 限制”：沿用首张封面的颜色、字体、短文案和人物身份，重新安排标题、脸、手与留白；同时附首张成品和原人物照片。只要求9:16时直接生成9:16，无须先生成未请求的3:4。
- 将工具原始输出**复制**到本次任务目录，保留原始文件。文件名带画幅，例如 `封面-3x4.png`、`封面-9x16.png`；可存项目根目录或 `output/`，最终链接必须指向实际位置。
- `generation.json` 记录：风格选择文件、实际引擎、每张图的提示词文件、参考图路径、工具原始路径、交付路径、实际宽高、请求比例和目视检查结果。本地追溯记录可用绝对路径；对外分享时使用随包相对路径，去除机器临时目录。
- 逐张读文件核实像素尺寸并检查中文字、人物身份与遮挡。生成器像素取整可能使比例略有偏差，记录真实值；原生约1.5MP图片不能称为4K，提示词写高清不代表已达到指定分辨率。
- 回复附成品与文件夹的可点击路径。用户说“打开”时打开本次成品；macOS可用当前环境允许的原生预览应用，批量选中所需PNG，不把打开文件夹或打开对话框当成已展示图片。
- 使用可用且获准的界面工具，读回窗口标题或缩略图列表，确认所有请求图片已载入才报告已打开。若工具阻止某个打开动作，说明实际阻碍并提供文件路径，不换通道绕过限制。

## 来源与适配边界

本 Skill 汇总已经试用的视觉原则，并保留各自署名链接；不是把外部 Skill 全部安装后套娃执行。oil 预设不是上游的视频选帧与头像合成流水线；baoyu 预设按小伟 IP 需要采用真人而非常规简化人物。9:16、16:9是本 Skill 的跨画幅适配。

现有 Claim-to-Pixel v1 契约仍只覆盖小红书3:4、公众号21:9和1:1，以及其确定性HTML输出。不要把额外9:16/16:9或imagegen结果声称为通过v1签核的产物；它们仍需保留FACTS.md、素材来源和实际生成记录。随机功能不改变事实与发布权限规则。
