# 灵感到封面：Design DNA 工作流

这份规则把网页设计灵感转成可执行的静态封面决策。参考站点用于训练眼睛和提炼方法，不用于复制页面、人物、文案、Logo 或具体坐标。

## 参考来源各自解决什么问题

| 来源 | 可借鉴的方法 | 不应照搬的内容 |
|---|---|---|
| [Awwwards](https://www.awwwards.com/) | 用 Design / Usability / Creativity / Content 四个维度复核作品。静态封面对应为层级、缩略图可读性、一个独特视觉锚点、真实内容。 | 网页滚动、WebGL 或动效本身不能直接当成封面装饰。 |
| [Recent Design](https://recent.design/) | 用 Web、Interface、Branding、Product、Typography、Motion、3D、Editorial 等标签定义参考方向。 | 不把标签变成关键词堆砌。每套只选一个主方向和一个辅助方向。 |
| [Muzli](https://muz.li/) | 通过持续策展、搜索、颜色和收藏建立个人灵感池；先收集，再归纳重复出现的规律。 | 不把每日流行视觉误认为适合当前选题的固定皮肤。 |
| [Designspiration](https://www.designspiration.com/) | 同时保存图片、颜色、链接、截图和笔记，形成 moodboard，而不是只保存一张好看的图。 | 不把第三方图片直接塞进公开封面；外部素材需要权利记录。 |
| [Design Spells](https://designspells.com/) | 从 Interaction、Transition、Easter Egg、3D、Button 等分类中提炼一个“签名细节”。静态封面把它转译成路径、叠层、揭示、光标或状态变化的画面线索。 | 不把多个动效都画成发光箭头；签名细节最多一个。 |
| [Loadmo.re](https://loadmo.re/) | 关注移动端、实验性、Brutalist、Editorial、Glitch、Tactile、Typography、Use of Camera 等主题，并坚持手机缩略图检验。 | 不为了前卫而牺牲标题、脸和证据的识别。 |
| [weilanx-cover-skill](https://github.com/Azure12355/weilanx-cover-skill) | 保持标题→人物→主题卡的层级；用前景/中景/背景和主题相关信息卡组织画面；每个比例原生重排。 | 不复制其样图人物、文案、颜色或布局。 |
| [xialingguo-ip](https://github.com/peggykangkang02/xialingguo-ip) | 用一张简短表单确认标题、风格、视觉重点、真人姿势；默认 21:9；把“标题 / 人物 / 产品 / 流程 / 结果 / 故事”作为主视觉焦点。 | 不把风格库变成固定模板，也不强迫用户连续回答无关问题。 |

## Design DNA 提取表

用户提供一张或多张参考图时，先写出下面六项，再开始生成：

1. **层级**：第一眼、第二眼、第三眼分别看到什么。
2. **构图**：对称、左右分区、路径流、卡片矩阵、叠层拼贴或大标题海报。
3. **排版**：字重、行数、对齐方式、描边/阴影、标题占比和留白。
4. **色彩与材质**：主色、强调色、背景材质、边缘和光线，不只写“高级”。
5. **密度与节奏**：前景/中景/背景的元素数量，哪里留白，哪里形成视觉冲刺。
6. **签名细节**：只选一个可转译为静态画面的互动线索，例如揭示、进度、路径、叠层、光标或状态切换。

提取结果进入项目 `COVER_PROMPT.md` 的“视觉 DNA”段落。写“借鉴规律”，不写“照着这张图复刻”。

## 视觉重点表单

信息不足时一次性展示这四项，只补问会改变结果的缺口：

1. **标题/主题**：完整标题或文章要解决的问题。
2. **视觉重点**：标题、真人、产品/界面、流程、结果、故事场景，选择一个第一主角。
3. **真人参考**：哪张图锁身份；姿势是 `content_driven` 还是 `source_locked`。
4. **目标画幅**：默认公众号 `21:9 + 1:1`，或指定其它比例。

用户说“你帮我选”时，直接根据内容路由和参考 DNA 给出一个主方案；最多再补问 1–2 个关键问题。

## 四维发布复核

在缩略图和大图都检查一次：

- **Design 40**：标题、人物、主题对象的层级是否清楚，颜色和材质是否服务内容。
- **Usability 30**：360px 宽时能否读出主题、脸和主证据；脸、手、标题没有碰撞。
- **Creativity 20**：是否只有一个有记忆点的构图或签名细节；删除无意义装饰。
- **Content 10**：标题、版本、数字、排名和场景是否有来源，概念图是否明确不会被误认为实测证据。

这不是对网页奖项的模拟打分，而是把网页设计的复核思路转成封面发布门。任何一项明显失败都要重排或降级主张，不能靠加特效掩盖。

## 版权和隐私边界

- 参考图只提供视觉语言；人物身份必须来自用户授权的人像参考。
- 外部站点的截图、Logo、作品和现场照片进入项目之前，要写入 `assets/SOURCES.md` 并标注权利状态。
- 公开仓库只提交规则、提示词和获得许可的样例，不提交用户私人肖像、机器本地路径或未授权参考图。
