两类都要时，创建 `article/` 与 `video/` 两个任务目录，各写 COVER_PROMPT.md、各选风格、各做文案。共用身份及事实，不能把公众号横幅当视频横版，也不把竖图裁成公众号图。没有明确平台时，先按公域社媒封面处理，不擅自生成公众号专用尺寸。旧 Claim-to-Pixel 的三比例 HTML 契约作为专门的历史验证路径保留，不要求重写既有项目。

## 当前视频系列优先规则

后续用户明确统一风格：video_social默认 `series`，参考 series-cover.md。上传照片只用于身份，新生成写实人物；不按每期主题重选皮肤。下列旧选型步骤仅适用于其它渠道或明确的风格实验，不能覆盖统一系列要求。

## 选择顺序

1. 从内容提炼：读者为什么点开、唯一主标题、唯一可见结果/对象。
2. 先读 identity-and-pose.md，默认锁定身份并按内容改变动作，纪实才锁原姿态。选人物角色：推荐者、现场参与者、操作演示者、讲解者；选择符合角色的现有照片或视频帧。默认开会照仅当说话/演讲本身合理时使用。照片少时可保留自然表情；不要凭空制造体验、合影、地点。
3. 选画面骨架：现场见闻 / 工具教程 / 观点冲突 / 成果证据。无数据就不选排名/成绩证明。
4. 根据参考图和材料选具体 style，写出一句理由，运行选择器 `--style ID`。`auto` 是 Agent 的判断职责，不是选择器的随机开关。用户明确要求随机时才用 `--style random`。
5. 每类先生成一张验证最重要的构图；通过后再做同类其他比例。

6. 有灵感网站、参考图或 moodboard 时，先按 `references/inspiration-playbook.md` 提取 Design DNA，再选风格和视觉重点；参考不等于模板。

COVER_PROMPT.md 至少记录：channel、选题、点击理由、人物角色与素材理由、骨架、style及选择理由、逐字文案白名单、主对象及来源、无真实素材时的表达边界。

不要把以上内容变成固定问卷；依据已知材料完成判断。用户仅问可行性时，清楚区分规则已实现与图片已实测的部分，不承诺稳定成功率或点击率。
