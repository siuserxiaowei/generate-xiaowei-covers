# 小伟封面视觉系统

## 固定识别

- 使用浅色纸张底、细网格或克制纹理、黑色粗标题、单一强调色。
- 标题负责说明主题，截图、模型卡、对比表、公告原文或现场照片负责证明主题。
- 人物默认出现在 3:4 和 21:9 的左下角；公众号 1:1 是单独创作的纯排版例外，除非用户明确要求人物。
- 人物卡必须保留脸、手、话筒以及与动作有关的桌面或物件。宁可缩小照片，也不要截断动作。
- 每张图只使用一种强调色。不同内容包可以换色，但同一成对封面不可混色。
- 不使用装饰性贴纸、无意义图形、伪造界面或无法核实的数据。

## 画幅

| 用途 | 尺寸 | 规则 |
|---|---:|---|
| 小红书竖版 | 1080×1440 | 标题在上半区；人物左下；证据模块占右下或中下。 |
| 公众号主封面 | 2100×900 | 独立横版构图；标题位于左上或中左；人物左下；证据模块占右侧 50%–60%。 |
| 公众号方封面 | 1080×1080 | 单独压缩标题；默认纯排版，不从横版裁切，不放小字。 |

公众号任务必须同时产出 `21:9` 与 `1:1`。两者共享主题和强调色，但标题、换行和元素位置分别设计。

## 标题

- 21:9 主标题优先一行，中文约 8–14 字；确需两行时必须手动断句。
- 1:1 从长标题提炼为 4–10 个中文字符或两个短行，删除“如何、为什么、我来告诉你”等前导语。
- 标题在缩小到 360px 宽后仍应先于图标和正文被识别。
- 一张封面最多一个高亮短语。高亮色块不能覆盖整段标题。

## 横版空间分配

默认 21:9 结构：

- 左侧标题区：约 42%。
- 左下人物区：约 16%–20%，使用横向或接近方形的环境照片卡。
- 右侧证据区：约 50%–56%，根据内容路由切换为模型卡、界面、矩阵、流程、公告或照片。
- 顶部识别条：品牌/栏目在左，作者系列在右。
- 不把竖版等比缩小后放入横版，也不靠裁切得到方版。

六种横版证据模块：

1. `model_release`：右侧模型卡或发布摘要。
2. `tool_tutorial`：右侧大界面，步骤在界面内部可见。
3. `model_comparison`：右侧横向矩阵，最多三对象、四维度。
4. `workflow`：右侧三角色或三阶段流程。
5. `official_evidence`：右侧公告/文档摘要和三条重点。
6. `field_recap`：左侧或下方大现场照片，右侧三条复盘。

## 人物策略

默认素材：`assets/portrait/xiaowei-context.jpg`。

- 竖版人物卡建议 300–360px 宽，固定左下。
- 21:9 人物卡建议 300–380px 宽，固定左下；标题与人物上下分层，不让脸压住标题。
- 1:1 默认不放人物，以短标题保证微信列表小尺寸识别；若用户要求人物，必须单独重排而非裁切横版。
- 现场复盘允许将照片扩大为主要证据，但人物仍位于画面左半区域。
- 每次使用照片都显式设置 `object-position`，并在 HTML 中写主体位置注释。
- 只有背景干净、边缘可靠且动作不会残缺时才使用透明抠图。

## 官方素材与联网研究

- 优先从官方产品站、官方文档、官方 GitHub、品牌资源包和原始公告获取 Logo、截图和产品图。
- 下载素材后写入任务目录的 `assets/SOURCES.md`：文件名、来源 URL、获取日期、用途、授权或商标说明。
- 封面上的版本、日期、参数、价格、排名和发布状态必须逐项写入项目根 `FACTS.md`，并指向官方证据位置。
- 官方组织头像可作为内部样稿的品牌提示，不自动视为可公开传播的品牌 Logo。
- 易变事实必须在当前日期重新核实，不能因为 Skill 内有旧样稿就复用旧数字。

## 输出检查

- 核对尺寸、文件名和全部素材是否存在。
- 生成 360px 宽缩略图检查标题、人物和证据。
- 检查人物手部、脸部和关键物件没有被裁断。
- 检查标题里的版本、日期、价格、参数和排名均有来源。
- 公众号方封面必须是独立构图和短标题。
- 发布前确认 `FACTS.md` 中没有待核实项，品牌图形也已按其官方使用规范复核。
